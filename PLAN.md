# План развития pcb-design-review

## Цель

Превратить существующую инженерную методику в проверяемый переносимый skill с машинным каталогом, профильными ограничениями, KiCad adapter и отчётами; сохранять human sign-off для safety/EMC.

## Этапы

1. **v0.2 / правила**: формализовать полный rule registry, согласовать критичность, описать applicability и отсутствие данных, проверить ссылки и структуру. Текущий набор — draft, ещё не нормативно утверждённый.
2. **v0.3 / профили и схема**: реализованы локальный CLI, отбор по признакам, планы Markdown/JSON, матрица критериев, проверка численных результатов, целостности JSON-доказательств и инженерных исключений. Матрица поддерживает подтверждение критерия и обработку численных расхождений источников. Далее согласовать проектные критерии и процесс утверждения исключений.
3. **v0.4 / KiCad read-only**: с KiCad 10.0.8 проверены импорт DRC v1, сверка XML-нетлиста, чтение стека, запуск ERC/DRC, сопоставление геометрических замечаний, сверка монтажных отверстий, ширины дорожек, зазора до линейного контура и зазора выбранных пар прямых дорожек. Добавлены диагностика окружения и матрица CLI/API для веток 8.0–10.0. Для старого API предусмотрено чтение геометрии без классификации меди вокруг NPTH. Далее нужны нативные прогоны с 8.0 и 9.0 и сверка с согласованным механическим чертежом проекта.
4. **v0.5 / power/EMC**: модель связности coil-contact-driver, DC/DC loops, TVS placement, GND continuity, список гипотез и A/B проверок. Требуется измерительная верификация.
5. **v0.6 / high speed**: FPGA/SFP+/10G, модели канала и constraints по datasheet, summary по SI и границам моделирования.
6. **v1.0 / quality gate**: добавлен CI для схем, каталога, профилей, учебного отчёта и тестов на Python 3.10 и 3.14. Инженерные отчёты экспортируются в Markdown, JSON и SARIF. Далее нужны воспроизводимые прогоны на fixture boards с ожидаемыми замечаниями, sign-off и changelog.

Замечания по текущему устройству репозитория и приоритеты перечислены в [своде ревью](PROJECT_REVIEW.md).

## Риски

- Ложное ощущение подтверждённого EMC или electrical safety из чистого DRC.
- Копирование произвольных численных параметров на другой stackup/фабрику.
- Несовместимость pcbnew API и версий KiCad.
- Неправильное толкование AI геометрии без схемы/PCB/контекстных моделей.
- Загрузка закрытых спецификаций в публичный GitHub.
