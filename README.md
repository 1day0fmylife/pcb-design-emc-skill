# PCB Design & EMC Review

Переносимый skill для **Codex и Claude Code**: проектирование и ревью печатных плат, размещение и трассировка, питание, SI/PI, диагностика паразитных связей, EMI/EMC и открытые меры снижения ПЭМИН.

Имя skill: `pcb-design-review`. Репозиторий: `pcb-design-emc-skill`.

## Возможности

- Анализ схемы и PCB: pin mapping, корпуса, placement, обратные токи, stackup, constraints и согласованность схемы с платой.
- Питание: power tree, sequencing, DC/DC, развязка, PDN, transient response, back-power, тепловые режимы и worst-case параметры.
- Интерфейсы: Ethernet, SFP/SerDes, DDR, clocks, FPGA I/O и управляющие шины.
- Наводки: гипотезы «источник → путь связи → чувствительный узел», A/B диагностика, альтернативные причины и проверка исправлений.
- EMI/EMC: эмиссия, устойчивость, корпус, кабели, фильтры, защиты и план измерений.
- ПЭМИН: открытые меры снижения связи и требования к отдельной профессиональной оценке.
- Верификация: ERC/DRC, анализ исключений, модели и измерения, план первого включения и отчёт о непроверенных пунктах.

Skill требует обосновывать ограничения документацией конкретных компонентов и отделять факты от гипотез. Не назначает одинаковые номиналы, зазоры или число слоёв всем платам.

## Подключение к проекту

Инструкции рассчитаны на локальные Codex и Claude Code. Они не устанавливают CAD, MCP, модели или измерительное ПО и не выдают дополнительных разрешений агенту.

### 1. Получить исходники

```sh
git clone https://github.com/1day0fmylife/pcb-design-emc-skill.git
cd pcb-design-emc-skill
```

Прочитайте `SKILL.md` и references. Для воспроизводимой командной установки выберите проверенный commit/tag, переключитесь на него и запишите SHA в документации своего проекта. Команды ниже выполняются **из корня клона skill**.

### 2. Установить в Codex

Укажите абсолютный путь к своему проекту:

```sh
project_dir=/absolute/path/to/your-project
skill_target="$project_dir/.agents/skills/pcb-design-review"
mkdir -p "$project_dir/.agents/skills"
# mkdir без -p остановит установку, если такая версия уже существует.
if mkdir "$skill_target"; then
  cp SKILL.md "$skill_target/"
  cp -R references rules profiles schemas scripts "$skill_target/"
fi
```

### 3. Установить в Claude Code

```sh
project_dir=/absolute/path/to/your-project
skill_target="$project_dir/.claude/skills/pcb-design-review"
mkdir -p "$project_dir/.claude/skills"
if mkdir "$skill_target"; then
  cp SKILL.md "$skill_target/"
  cp -R references rules profiles schemas scripts "$skill_target/"
fi
```

При использовании обоих агентов установите обе копии из одной ревизии. При обновлении сравните установленную версию с исходником и сохраните локальные правки. В состав установки входят `SKILL.md`, `references/`, `rules/`, `profiles/`, `schemas/` и `scripts/`.

Откройте новую сессию агента в целевом проекте и проверьте наличие skill. Если он не обнаружен, проверьте путь, YAML frontmatter, настройки доверия/политики клиента и документацию вашей версии. Для командного использования можно добавить установленные каталоги в Git проекта после review.

```text
$pcb-design-review Проведи ревью схемы и платы в hardware/controller.
Проверь питание, размещение, обратные токи, SI/PI, EMI и открытые меры
снижения ПЭМИН. Сначала изучи правила проекта и требования.
Выдай находки с RefDes/net/layer, основаниями и планом проверки.

```

Claude Code:

```text
/pcb-design-review Проведи ревью hardware/controller: питание, SI/PI,
EMI и открытые меры снижения ПЭМИН. Только анализ, без изменения CAD.
```

Другие примеры:

```text
Проверь power tree и подготовь план первого включения.

Не назначай исправление без проверки пути связи.

Проверь полноту правил и исключения в отчёте DRC.
Отдельно укажи, какие свойства платы этим отчётом не проверены.
```

## Конфигуратор PCB-профиля

CLI работает локально в Python 3.10+ с PyYAML 6 и jsonschema 4. Зависимости перечислены в [scripts/requirements.txt](scripts/requirements.txt).

```sh
python3 scripts/pcb_profile.py list --fields
python3 scripts/pcb_profile.py analyze relay-controller
python3 scripts/pcb_profile.py init my-controller --from industrial-24v \
  --description "Контроллер с реле" --feature relay --feature external-ports \
  --output my-controller.yaml
```

Укажите в созданном YAML ревизию платы, признаки, ссылки на артефакты и параметры, для которых есть документ с редакцией и областью применения. Затем проверьте профиль и сформируйте план ревью.

```sh
python3 scripts/pcb_profile.py validate my-controller.yaml
python3 scripts/pcb_profile.py analyze my-controller.yaml --output review-plan.md
python3 scripts/pcb_profile.py analyze my-controller.yaml --format json --output review-plan.json
```

План содержит выбранные правила, причины и способы проверки, рекомендации, недостающие данные и основания для исключений. Команда использует только данные профиля. Численные критерии указываются пользователем, а результаты фактических проверок оформляются отдельно. Семантика наследования и статусов описана в [регламенте](references/rules-engine.md).

### Учебный сценарий с релейным контроллером

В [учебном профиле](examples/relay-review/profile.yaml) заданы две пары доменов. План запрашивает отдельные `clearance` и `creepage` для каждой пары и показывает пробелы в критериях. Готовый учебный DRC содержит активное замечание и исключение.

```sh
python3 scripts/pcb_profile.py analyze examples/relay-review/profile.yaml
python3 scripts/pcb_profile.py import-drc examples/relay-review/profile.yaml \
  examples/relay-review/drc.json --context examples/relay-review/drc-context.yaml
python3 scripts/pcb_profile.py validate-report examples/relay-review/profile.yaml \
  examples/relay-review/review.json
```

Импорт работает с готовым JSON KiCad DRC v1 и привязывает объекты по UUID из предоставленного контекста. Инженерный отчёт после проверки можно сверить с профилем командой `validate-report`. Форматы матрицы, контекста и доказательств описаны в [регламенте](references/rules-engine.md).

Если в отчёте объявлен `evidence_artifacts`, `validate-report` проверяет SHA-256 локальных JSON-файлов и наличие записей, на которые ссылаются замечания. [Учебный отчёт](examples/relay-review/review.json) · [Формат реестра](references/rules-engine.md#целостность-артефактов)

`export-report` проверяет инженерный отчёт и выгружает его в Markdown, JSON или SARIF 2.1.0. В представлениях сохраняются исходные статусы, приоритет и уверенность, когда они заданы в замечании. [Команда и форматы экспорта](references/rules-engine.md#экспорт-инженерного-отчёта)

Инженерное исключение записывается в подтверждённый `FAIL` с ID, владельцем, причиной, ревизией и сроком. Валидация сохраняет статус `FAIL` и отклоняет исключения по электробезопасности. [Формат исключения](references/rules-engine.md#инженерные-исключения)

Профиль поддерживает минимальный зазор меди для пары классов сетей и отдельные критерии по режимам. При импорте `clearance` KiCad предлагает критерий пары, когда обе сети известны и UUID привязаны к соответствующим классам. [Пример описания пары](references/rules-engine.md#пары-классов-сетей)

В матрице можно указать владельца и дату подтверждения критерия, а также значения из альтернативных источников. При расхождении план требует зафиксировать выбранный источник и обоснование для текущей ревизии. [Подтверждение источников](references/rules-engine.md#подтверждение-и-расхождения-источников)

Геометрические замечания DRC сопоставляются с кандидатами правил по типам KiCad. Инвентарь PCB сохраняет признак PTH или NPTH, форму, размеры и центр отверстия, а для паза также направление оси. [Таблица сопоставлений](references/rules-engine.md#сопоставление-геометрии-drc)

`compare-trace-width` читает ширину отрезков и дуг из PCB и сверяет её с минимумом или максимумом профиля. Список дорожек задаётся по UUID. В JSON сохраняются измерение, критерий и его источник. [Пример запуска и охват](references/rules-engine.md#сверка-ширины-дорожек)

`compare-copper-edge` сверяет номинальный зазор между выбранными прямыми дорожками и замкнутым контуром `Edge.Cuts` из отрезков и прямоугольников. Расчёт учитывает ширину меди и внутренние вырезы. [Формат входов и охват](references/rules-engine.md#сверка-зазора-меди-до-края)

`compare-copper-gap` измеряет номинальный зазор между указанными парами прямых дорожек разных сетей на одном медном слое. Минимум берётся из критерия класса или пары классов для выбранного режима. [Пример запуска и охват](references/rules-engine.md#сверка-зазора-между-дорожками)

Реальный экспорт проверен с `kicad-cli` 10.0.8 на официальной QA-плате. Прогон подтвердил обработку двух нарушений максимальной ширины дорожки и совпадение замечаний при разных кодах завершения. [Воспроизводимый прогон KiCad](examples/kicad-multinetclasses/README.md)

Команда `inventory-board path/to/file.kicad_pcb` читает объекты платы по UUID. Опция `import-drc --board path/to/file.kicad_pcb` добавляет к замечаниям сети, слои и RefDes из платы. Для этих режимов нужен модуль `pcbnew` из локальной установки KiCad в используемом Python. Импорт с готовым контекстом работает и без модуля. [Поля и границы инвентаря](references/rules-engine.md#чтение-платы-по-uuid)

`compare-netlist` сверяет нативную PCB и XML-нетлист KiCad по `RefDes`, номеру вывода и имени сети. Отчёт показывает пропущенные компоненты и площадки, лишние подключённые площадки и несовпадения сетей. Для подтверждённой сверки укажите общую ревизию обоих файлов. [Пример экспорта и сверки](examples/kicad-netlist/README.md)

Если установленный `pcbnew` не умеет определять наличие меди вокруг NPTH, геометрия отверстий остаётся доступной. Сверка сетей помечает затронутые выводы как `REVIEW_REQUIRED` и сохраняет UUID площадок. [Чтение платы по UUID](references/rules-engine.md#чтение-платы-по-uuid)

`inventory-stackup` читает физический стек из нативной PCB. В JSON попадают порядок слоёв и подслоёв, явно заданные толщины, материалы и диэлектрические параметры. При отсутствующем или неполном стеке выводится `REVIEW_REQUIRED`. Команда использует локальный `pcbnew`. [Формат и пример запуска](references/rules-engine.md#физический-стек-платы)

`compare-stackup` сопоставляет данные PCB с допусками, порядком слоёв и указанными свойствами из согласованного листа изготовителя. В отчёте сохраняются ссылки на ревизии и SHA-256 входных файлов. [Шаблон листа](examples/fabrication-stackup.example.yaml) · [Порядок сверки](references/rules-engine.md#сверка-стека-с-изготовителем)

`compare-mounting` сопоставляет указанные по UUID монтажные отверстия с чертежом. Проверяются координаты, форма и размеры, металлизация и угол оси продолговатого отверстия. Результат содержит ревизию и SHA-256 входов. [Шаблон критериев](examples/mechanical-holes.example.yaml) · [Порядок сверки](references/rules-engine.md#сверка-монтажных-отверстий-с-чертежом)

`run-checks` запускает локальные ERC и DRC на временной копии проекта. В выходном каталоге остаются исходные JSON KiCad и `summary.json` с версией, кодами завершения, охватом и SHA-256 входов. [Команды и статусы](references/rules-engine.md#локальный-запуск-erc-и-drc)

`probe-kicad` показывает версии и пути установленных `kicad-cli` и `pcbnew`, проверяет флаги CLI и наличие методов Python для чтения платы. Для диагностики достаточно запустить `python3 scripts/pcb_profile.py probe-kicad`. [Матрица совместимости](references/rules-engine.md#совместимость-kicad)

## Входные данные и результат

Полезны нативные схема/PCB, BOM с точными part numbers, stackup изготовителя, datasheet/errata, механика и корпус, питание/нагрузки, интерфейсы, условия эксплуатации и требования к испытаниям. Для диагностики нужны воспроизводимые условия и измерения. Секретные материалы не передаются во внешние сервисы.

При неполных входах агент должен продолжить доступный анализ, обозначить TBD и не выдавать отсутствие проверки за успешный результат. Скриншот не заменяет нативный проект.

Результат: охват ревью, находки с приоритетом и доказательствами, уверенность в дефекте и исправлении, компромиссы, проверочный план, выполненные проверки и остаточные риски. Правила ADR/ICD и sign-off определяются конкретным проектом; skill не утверждает эти решения за инженера.

## Статус проверки и ограничения

В исходном проекте выполнены проверка структуры skill и локальных Markdown-ссылок, статический анализ инструкций и независимый текстовый прогон трёх сценариев: неполные данные по PHY/DC/DC, проект без ADR и DRC с нарушениями при exit code 0. Для автономной поставки дополнительно проверяются структура и ссылки.

Конфигуратор и операции с KiCad проверяются командами `python3 scripts/pcb_profile.py validate` и `python3 -B -m unittest discover -s tests -v`. Нативный запуск ERC и DRC проверен с KiCad 10.0.8 на демонстрационных и QA-платах. В [своде ревью репозитория](PROJECT_REVIEW.md) перечислены замечания и приоритеты развития автоматизации.

GitHub Actions проверяет схемы, каталог, профили, учебный отчёт и тесты на Python 3.10 и 3.14 для каждого PR и обновления `main`. Тесты, которым нужны локальные KiCad и демонстрационные платы, пропускаются при их отсутствии. [Конфигурация CI](.github/workflows/validate.yml)

Загрузка реальными клиентами Codex/Claude Code, ревью нативной платы и измерения на стенде пока не подтверждены. Skill является инженерным помощником, не заменяет квалифицированное review, расчёты и испытания.

**Соответствие EMC/TEMPEST не подтверждается AI, ERC/DRC, моделированием или одной предварительной лабораторной проверкой.** Формальный статус возможен только по утверждённой программе уполномоченной организации. Снижение эмиссии не доказывает отсутствие утечки информации. Закрытые нормы ПЭМИН, ключи, секретные параметры и конфиденциальные результаты не должны попадать в этот репозиторий.

## Развитие

1. Проверить подключение в актуальных Codex и Claude Code и зафиксировать версии клиентов.
2. Создать несекретные учебные KiCad-проекты с известными дефектами и критериями оценки ответов.
3. Добавить локальный version-aware запуск ERC/DRC с сохранением отчётов, без автоматической правки платы.
4. Подготовить шаблоны power budget, constraint matrix и отчёта ревью.
5. Провести review профильным инженером по SI/PI и EMC, затем уточнить правила по результатам реальных измерений.
6. Выбрать и добавить лицензию перед распространением на её условиях; лицензия пока не определена.
