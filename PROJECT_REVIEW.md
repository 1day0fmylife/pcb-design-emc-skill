# Свод ревью проекта pcb-design-review

В репозитории есть переносимая методика ревью, черновой каталог из 180 правил в 19 семействах, шесть стартовых профилей, JSON Schema и пример отчёта. Методика различает функциональные проблемы, электробезопасность, эмиссию, устойчивость и ПЭМИН. Исходные данные конкретной платы в репозитории отсутствуют. Ниже приведены замечания к инструменту и его данным.

## Что было исправлено

- Профили ранее служили шаблонами. Локальный CLI теперь учитывает наследование, отбирает правила по признакам и объясняет неопределённую применимость и исключения.
- Числа в схеме профиля можно было указать без прослеживаемого основания. Конфигуратор теперь запрашивает документ, редакцию и область применения каждого используемого значения и сбрасывает унаследованный источник при перезаписи числа.
- В описании каталога `BLOCKER` одновременно описывал тяжесть и подтверждённость нарушения. Теперь тяжесть отделена от статуса. План ревью и [пример отчёта о проверке](examples/review-result.example.json) имеют разное назначение.
- Инструкции установки обновлены под CLI, а команда `validate` проверяет схемы, наследование, ID и ссылки каталога.
- Добавлены матрица по объектам и режимам и проверка связей между критериями и доказательствами. В [учебном релейном сценарии](examples/relay-review/profile.yaml) две пары доменов и отдельные строки для clearance и creepage.
- Готовый KiCad DRC JSON можно импортировать с привязкой к объектам по UUID. Синтетический сценарий сохраняет активное замечание при коде завершения 0 и помечает исключение отдельно.
- Реальный импорт проверен на QA-плате `multinetclasses_drc` в KiCad 10.0.8. Для сопоставления замечаний по ширине добавлено явное направление границы. [Прогон KiCad](examples/kicad-multinetclasses/README.md)

| P0 | [Схема результатов](schemas/report.schema.json) проверяет наличие и согласованность деклараций о доказательстве. | Определить формат версионированного реестра артефактов и правила подтверждения их происхождения, применимости и охвата. |
| P1 | [Каталог](rules/catalog.yaml) содержит преимущественно формулировки действий и ссылки на общие разделы. Для EMC вести отдельные матрицы эмиссии и устойчивости. |

Следующие учебные сценарии могут дополнить релейный пример высокоскоростным каналом и моделью импульсного питания. Для каждого нужны входные файлы, ожидаемые ID и статусы, а также причина каждого исключения. В оценке ПЭМИН достаточно зафиксировать разрешённую область, ответственность и необходимость отдельной процедуры. Испытания и подтверждение безопасности остаются задачами компетентных специалистов.
